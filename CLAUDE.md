## Commands

```bash
npm run dev       # Vite dev server (serves index.html with src/ sandbox)
npm run build     # tsc type-check + Vite library build → dist/
npm run fix       # ESLint --fix + Prettier --write across all TS/JS/HTML files
npm run preview   # Preview the production build locally
```

There is no test suite.

## Architecture

This is a published npm library (`@vladislavbelozerov/js-app`) — a lightweight DOM component runtime.

**Two source trees:**
- `lib/` — the library source that gets bundled and shipped. Entry point: `lib/main.ts`.
- `src/` — a local sandbox app for manual testing during development (not published).

**Build output:** `dist/` — a single ESM bundle (`dist/js-app.js`) plus `.d.ts` type declarations generated by `vite-plugin-dts` from `lib/`. The `tsconfig-lib.json` handles lib-specific TS config for the DTS plugin.

**Core data structures (all in `lib/App.ts`):**

The singleton `App` object holds two Maps and several RxJS subjects:
- `App.registry: Map<string, RegistryRecord>` — registered component definitions (name, selector, component fn, default props).
- `App.components: Map<string, ComponentItem>` — live component instances keyed by UID. Each item stores `{ id, selector, name, ref }`.

**Initialization flow:**

1. Consumer calls `addToRegistry([registerComponent(...)])` to populate `App.registry`.
2. Consumer calls `initApp(root)` which calls `initComponents(root)`.
3. `initComponents` queries each registered selector inside `root`. For each matching element not yet stamped, it calls the component function, stores the returned ref in `App.components`, and sets a `data-component-{kebab-name}-id` attribute on the element to prevent double-initialization.

**Component contract:** A component is `(element: HTMLElement, props: Props) => Ref`. The returned ref is stored verbatim. If ref has a `destroy()` method, `destroyComponents` calls it during cleanup.

**Hooks are thin RxJS wrappers over `App`'s subjects:**
- Lifecycle hooks (`useReady`, `useBeforeDestroy`, etc.) subscribe to the corresponding Subject on `App`.
- `useProps(element, name, defaults)` reads `element.dataset` keys namespaced by `{name}`, auto-coerces JSON/booleans/numbers.
- `useRef<C>(element, name)` returns a `BehaviorSubject` that resolves — after a `setTimeout` inside `useReady` — to the ref of the component instance stamped on `element`.

**External dependencies:**
- `rxjs` — peer dependency; used for all reactive state (subjects, observables).
- `lodash-es` — runtime dependency; used for `kebabCase`/`camelCase` in prop parsing and ref lookup.
